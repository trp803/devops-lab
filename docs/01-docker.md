# Docker — контейнеризация

## Что такое Docker и зачем он нужен

До Docker приложения запускались напрямую на сервере. Проблема: "у меня работает, а на сервере нет". Причина — разные версии библиотек, Python, Node.js, переменных окружения.

Docker решает это с помощью **контейнеров** — изолированных окружений, которые содержат всё необходимое для работы приложения: код, среду выполнения, библиотеки, конфиги. Контейнер одинаково работает на любом компьютере где установлен Docker.

**Аналогия:** Docker-контейнер — это как стандартный морской контейнер. Внутри может быть что угодно, но форма снаружи всегда одинаковая — любой корабль, поезд или грузовик может его перевезти.

## Ключевые понятия

### Image (Образ)

Образ — это шаблон только для чтения, из которого создаются контейнеры. Аналогия: образ = рецепт, контейнер = готовое блюдо.

Образ состоит из **слоёв (layers)**. Каждая инструкция в Dockerfile создаёт новый слой. Слои кешируются — если код изменился, но зависимости нет, Docker не переустанавливает их.

```
Image layers (снизу вверх):
┌─────────────────────────┐
│  COPY . .               │  ← слой 4: код приложения
├─────────────────────────┤
│  RUN npm install        │  ← слой 3: зависимости (кешируется)
├─────────────────────────┤
│  COPY package.json ./   │  ← слой 2
├─────────────────────────┤
│  FROM node:18-alpine    │  ← слой 1: базовый образ
└─────────────────────────┘
```

### Container (Контейнер)

Запущенный экземпляр образа. Контейнер — это процесс на хосте, изолированный с помощью:
- **namespaces** — изоляция: каждый контейнер видит свой PID, сеть, файловую систему
- **cgroups** — ограничения: сколько CPU и RAM может использовать контейнер

### Dockerfile

Файл с инструкциями для сборки образа. Каждая строка — инструкция:

| Инструкция | Что делает |
|---|---|
| `FROM` | Базовый образ |
| `WORKDIR` | Рабочая директория |
| `COPY` | Копировать файлы |
| `RUN` | Выполнить команду при сборке |
| `EXPOSE` | Документировать порт (не открывает!) |
| `ENV` | Переменная окружения |
| `USER` | От имени какого пользователя запускать |
| `CMD` | Команда при старте контейнера |

## Multi-stage build

Проблема: если собирать образ в один этап, в финальный образ попадают dev-инструменты, кеши npm, временные файлы — образ раздувается.

Решение — многоэтапная сборка. Используем два FROM:

```dockerfile
# Этап 1 — сборка (builder)
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install          # устанавливаем ВСЕ зависимости (включая dev)
COPY . .

# Этап 2 — продакшн образ
FROM node:18-alpine      # чистый образ
WORKDIR /app
# Копируем ТОЛЬКО нужные файлы из builder
COPY --from=builder /app .
CMD ["node", "app.js"]
```

Финальный образ не содержит npm кешей, временных файлов сборки — он меньше и безопаснее.

## Non-root пользователь

По умолчанию процессы в контейнере запускаются от **root**. Если злоумышленник взломает приложение — он получит root права внутри контейнера.

Лучшая практика — создать отдельного пользователя:

```dockerfile
RUN addgroup -g 1001 nodegroup && \
    adduser -u 1001 -G nodegroup -s /bin/sh -D nodeuser
USER nodeuser
```

Фиксированные UID/GID (1001) — важны: поведение одинаково на любом хосте.

## Docker Compose

Docker Compose — инструмент для запуска нескольких контейнеров как одного приложения. Конфигурация описывается в `docker-compose.yml`.

### Ключевые поля

```yaml
services:
  app:
    image: nginx:alpine       # Использовать готовый образ
    build: ./app              # ИЛИ собрать из Dockerfile
    ports:
      - "8080:80"             # host:container — открыть снаружи
    expose:
      - "3000"                # Только внутри Docker сети
    environment:
      - KEY=value             # Переменные окружения
    volumes:
      - ./data:/app/data      # Bind mount — папка хоста → контейнер
      - myvolume:/app/db      # Named volume — управляется Docker
    depends_on:
      - db                    # Стартовать после db
    restart: unless-stopped   # Политика перезапуска

volumes:
  myvolume:                   # Объявление named volume
```

### ports vs expose

- `ports: "8080:80"` — порт доступен **снаружи** (с хоста и интернета)
- `expose: "3000"` — порт доступен **только внутри Docker сети** (другим контейнерам)

Правильная архитектура: приложение через `expose`, только Nginx через `ports`.

### Сети Docker

Все контейнеры в одном `docker-compose.yml` автоматически попадают в одну сеть и могут обращаться друг к другу **по имени сервиса**:

```yaml
# Внутри контейнера app можно писать:
http://db:5432     # db — имя сервиса в docker-compose
http://redis:6379
```

### Named volumes vs Bind mounts

| | Named volume | Bind mount |
|---|---|---|
| Синтаксис | `myvolume:/data` | `./local:/data` |
| Управление | Docker | Вы сами |
| Использование | Данные БД, постоянные данные | Конфиги, код для разработки |
| Переносимость | Высокая | Зависит от структуры хоста |

## Как работает Docker изнутри

```
Вы пишете: docker run nginx

1. Docker проверяет: есть ли образ nginx локально?
   └── Нет → скачивает с Docker Hub (registry)

2. Создаёт контейнер:
   └── Создаёт namespace (изолированное окружение)
   └── Настраивает cgroup (лимиты ресурсов)
   └── Монтирует файловую систему образа (read-only)
   └── Добавляет writable слой поверх (для записи контейнера)

3. Запускает процесс (CMD из Dockerfile)
   └── Процесс видит только своё окружение
   └── Не видит процессы хоста
   └── Имеет свой сетевой интерфейс
```

## Команды Docker

```bash
# Образы
docker build -t myapp:v1 .          # Собрать образ
docker images                        # Список образов
docker pull nginx:alpine             # Скачать образ
docker rmi myapp:v1                  # Удалить образ

# Контейнеры
docker run -d -p 8080:80 nginx       # Запустить в фоне
docker ps                            # Запущенные контейнеры
docker ps -a                         # Все (включая остановленные)
docker stop mycontainer              # Остановить
docker rm mycontainer                # Удалить

# Отладка
docker logs mycontainer              # Логи контейнера
docker exec -it mycontainer sh       # Войти внутрь контейнера
docker inspect mycontainer           # Детальная информация

# Docker Compose
docker compose up -d                 # Запустить все сервисы
docker compose down                  # Остановить и удалить
docker compose logs -f               # Следить за логами
docker compose ps                    # Статус сервисов
```
